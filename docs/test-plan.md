# E2E Test Plan — AI Code Guardian

## Overview
End-to-end validation of AI Code Guardian across all components: detection, review, PR integration (comments/labels/check runs), audit logging, dashboard metrics, and Docker packaging.

## Test Scenarios

### T1 — Clean PR (no AI-generated code) — [#36](https://github.com/deghosal-2026/ai-code-guardian/issues/36)
| Field | Value |
|-------|-------|
| **Objective** | Verify zero false positives on human-written code |
| **Steps** | 1. Create PR with human-written code changes<br>2. Trigger guardian workflow<br>3. Check no violations reported |
| **Expected** | Comment: "No AI-generated code detected."<br>Label: low-risk<br>Check run: neutral ✅ |

### T2 — AI-generated markers detected — [#37](https://github.com/deghosal-2026/ai-code-guardian/issues/37)
| Field | Value |
|-------|-------|
| **Objective** | Verify marker-based detection works end-to-end |
| **Steps** | 1. Create PR with code containing `# Generated by Copilot` / `# Generated by Cursor` / `# Generated by Claude Code`<br>2. Trigger guardian workflow<br>3. Validate detection output |
| **Expected** | Comment lists AI-generated files with tool name and confidence<br>Label: medium-risk or higher<br>Check run: neutral (advisory mode) |

### T3 — Hallucinated API in diff — [#34](https://github.com/deghosal-2026/ai-code-guardian/issues/34)
| Field | Value |
|-------|-------|
| **Objective** | Verify hallucinated API rule fires on unknown dotted calls |
| **Steps** | 1. Create PR with code calling `some_bogus_lib.do_thing()`<br>2. Trigger guardian workflow<br>3. Validate violation |
| **Expected** | Violation: `hallucinated-api` for `some_bogus_lib.do_thing`<br>Label: medium-risk<br>Check run: neutral |

### T4 — Hardcoded secrets in diff — [#35](https://github.com/deghosal-2026/ai-code-guardian/issues/35)
| Field | Value |
|-------|-------|
| **Objective** | Verify hardcoded-secrets rule catches inline secrets |
| **Steps** | 1. Create PR with code containing `api_key = "sk-abc123..."`<br>2. Trigger guardian workflow<br>3. Validate violation |
| **Expected** | Violation: `hardcoded-secrets`<br>Label: critical-risk<br>Check run: neutral (advisory) |

### T5 — Missing error handling (bare except) — [#38](https://github.com/deghosal-2026/ai-code-guardian/issues/38)
| Field | Value |
|-------|-------|
| **Objective** | Verify missing-error-handling rule catches bare `except:` |
| **Steps** | 1. Create PR with `try: ... except: pass`<br>2. Trigger guardian workflow<br>3. Validate violation |
| **Expected** | Violation: `missing-error-handling`<br>Check run: neutral |

### T6 — Mixed violations across multiple files — [#39](https://github.com/deghosal-2026/ai-code-guardian/issues/39)
| Field | Value |
|-------|-------|
| **Objective** | Verify multiple violation types are aggregated correctly |
| **Steps** | 1. Create PR touching 3+ files with AI markers + secrets + bare except across files<br>2. Trigger guardian workflow<br>3. Validate aggregation |
| **Expected** | Comment groups violations by severity<br>Risk level = highest severity across all violations<br>Check run summary includes counts per rule |

### T7 — Comment truncation (>20 violations) — [#40](https://github.com/deghosal-2026/ai-code-guardian/issues/40)
| Field | Value |
|-------|-------|
| **Objective** | Verify comment truncation at 20 violations with note |
| **Steps** | 1. Create PR with 25+ violations across many files<br>2. Trigger guardian workflow<br>3. Validate truncation |
| **Expected** | Comment lists exactly 20 violations<br>Footer note: "...and 5 more violations" |

### T8 — Enforcement mode — [#41](https://github.com/deghosal-2026/ai-code-guardian/issues/41)
| Field | Value |
|-------|-------|
| **Objective** | Verify enforcement mode changes check run conclusion |
| **Steps** | 1. Set policy `governance_mode: enforcement`<br>2. Create PR with critical violations<br>3. Trigger guardian workflow<br>4. Validate check run failure |
| **Expected** | Check run conclusion: `failure` (critical) or `success` (low/medium)<br>Comment label says "ENFORCEMENT MODE" |

### T9 — Audit log entries created — [#42](https://github.com/deghosal-2026/ai-code-guardian/issues/42)
| Field | Value |
|-------|-------|
| **Objective** | Verify every analysis creates an audit log entry |
| **Steps** | 1. Run any guardian analysis<br>2. Read audit log file<br>3. Validate entry structure |
| **Expected** | JSONL file created in `GUARDIAN_AUDIT_DIR`<br>Each entry has timestamp, event_id, pr_number, violations, detection_results |

### T10 — Dashboard renders correctly — [#43](https://github.com/deghosal-2026/ai-code-guardian/issues/43)
| Field | Value |
|-------|-------|
| **Objective** | Verify dashboard loads and displays correct metrics |
| **Steps** | 1. Run several analyses with varying results<br>2. Start `guardian serve`<br>3. Open /dashboard and /api/stats<br>4. Validate metrics |
| **Expected** | /dashboard renders stats grid and bar chart<br>/api/stats returns correct total_prs, ai_prs, violation_trends<br>/metrics returns Prometheus-format metrics |

### T11 — Docker container runs detection — [#44](https://github.com/deghosal-2026/ai-code-guardian/issues/44)
| Field | Value |
|-------|-------|
| **Objective** | Verify the Docker image can run guardian commands |
| **Steps** | 1. Build docker image<br>2. Run `docker run --rm guardian:test version`<br>3. Run `docker run --rm guardian:test --help`<br>4. Verify expected output |
| **Expected** | `version` prints `ai-code-guardian v0.1.0`<br>`--help` prints usage |

### T12 — Label cleanup (old risk labels removed) — [#45](https://github.com/deghosal-2026/ai-code-guardian/issues/45)
| Field | Value |
|-------|-------|
| **Objective** | Verify that when risk level changes, old labels are removed |
| **Steps** | 1. Run analysis that sets `critical-risk` label<br>2. Run analysis on same PR that results in `low-risk`<br>3. Verify `critical-risk` removed and `low-risk` added |
| **Expected** | Only `low-risk` remains on PR<br>No duplicate or stale labels |

## Test Findings Record

- **Screenshots / logs** (if applicable)

- **Notes / observations**
